# 交换消除 pass 优化与验证

2026-11-02，在提交 `a702960` 的 SLL/LL 前端优化基础上修改
`CommutativeCancellationPass`。前端、CMake 构建模式、默认四轮优化流程均沿用
该提交；本次测试使用同一个本地 Debug 构建（C++ `-O0 -g2 -ggdb`）。

## 改动

- 门索引表、寄存器顺序表、输入门列表和角度合并列表按 `const &` 传递，
  查表取得引用，消除交换检查内反复复制整张表的开销。
- 一次建立 `(线路, Operation*) → 交换分组编号` 反向索引，替代候选门的
  反复分组扫描。索引只用于本次 pass 的分析阶段，IR 改写之后不再使用。
- CX/CX、CX 控制位上的 RZ、CX 目标位上的 RX 使用精确代数规则，跳过
  矩阵分配、Kronecker 积和矩阵乘法；其他情况继续使用既有判断。
- 同一控制线的交换分组中，允许越过另一目标位的门寻找可消除的同类门；
  两个候选门还必须属于目标线上的同一个交换分组。
- 每轮清空门表和寄存器表，避免保留上次分析的条目。

正确性测试还发现并修复了三处原有问题：

1. `CX(0,2); CZ(1,2); CX(0,2)` 不能因共享目标位就消除两个 CX。
   共享目标位的快捷判断现限定为相同受控 Pauli 轴；共享控制位的快捷判断
   也限定为已知受控 Pauli 门。
2. `BiMap` 按操作地址排序，不能用作线路顺序。合并/删除前按 `number`
   排序，避免 RX 合并等场景错误重连或崩溃。
3. `replace_x_z` 和 `delete_gate` 原先在检查范围前解引用 `it + 1`；
   现先检查边界，消除末尾迭代器越界。

## 性能

输入为 `tmp/ZZ20_全连接_原始_20q(1).qasm`，20 量子位、5,040 个门和
20 次测量，输出为 OpenQASM，无拓扑映射。

| 相同 Debug 构建下的测量 | 修改前 | 修改后 |
|---|---:|---:|
| 单次交换消除 pass | 401.2984 s | 5.5855 s |
| 隔离 pass 的整个编译进程 | 403.0230 s | 7.3278 s |
| 默认四轮 `-O1` 完整编译 | 本轮未重测 | 66.3307 s |
| 默认四轮中的交换消除累计 | 本轮未重测 | 22.6164 s |

隔离测试的自定义序列为 `2, 8`（交换消除、未使用调用清理），仍包含编译器
自动执行的前端、门分解、lowering 和后端。单次 pass 约快 **71.8 倍**。
这不是把单次 pass 与四轮总时间比较，也不与此前 Release 实验混用。
各配置本次测量一次，不是统计中位数，不包含编译器自身的构建时间。

默认四轮中，`ConsolidateBlocks` 现耗时 40.5843 s，成为主要热点。
本次没有改成单轮，也没有调整矩阵判等容差。

## 正确性

`test/test_commutative_cancellation.py` 包含 107 个线路：

- CX/CY/CZ 的同控制位、同目标位、反向、链式及不相交操作数组合；
- CX 与 RX/RZ 的可交换及不可交换位置；
- 奇偶数量抵消、RX/RZ 合并、H 非交换边界、SWAP 和多个量子寄存器；
- 40 个固定随机种子的 2–4 量子位混合门线路。

每个线路测试三种配置，共 **321/321 通过**：

| 配置 | 数量 | 验证口径 |
|---|---:|---|
| 单次交换消除 | 107 | 完整酉矩阵（允许整体相位）及末端测量映射 |
| 连续四次交换消除 | 107 | 同上，覆盖重复执行 |
| 默认完整 `-O1` | 107 | 对所有输入态的末端经典输出 POVM 等价 |

隔离测试的最大矩阵元素误差为 `6.28e-16`；完整流程的最大 POVM 元素误差
为 `7.77e-16`，阈值均为 `1e-7`。完整流程含独立的测量前对角门删除 pass，
因此使用末端经典输出语义，不能把这组结果解释为完整酉矩阵相同。
测试还断言典型线路的门数，避免用禁用 pass 的方式通过等价性检查。

ZZ20 另外验证：

- 修改前隔离 pass、修改后隔离 pass、修改后默认四轮输出逐字节一致。
- 输出指令序列恰好等于原输入删除一对相邻相同 CX，包含全部测量映射；
  由 `CX·CX=I` 得到该线路对任意输入态的等价性。
- 对全零态、交替计算基态、固定种子的随机乘积态各做一次完整 20q
  状态向量比较，三组归一化保真度均为 1，最大振幅误差均为 0。
- CX 从 4,000 降为 3,998，含测量深度从 4,247 降为 4,245。

## 复现

构建本地编译器和 MLIR API：

```bash
cmake --build build --target qllvm-compile qllvm-mlir-api -j 4
```

执行全部回归测试（环境需 numpy、qiskit）：

```bash
OPENBLAS_NUM_THREADS=1 /opt/anaconda3/envs/qllvm/bin/python \
  test/test_commutative_cancellation.py \
  --compiler build/bin/qllvm-compile \
  --work-dir tmp/commutation-regression \
  --modes isolated1 isolated4 full
```

不带 `--modes` 默认运行两种隔离测试。测试失败时返回非零退出码；每个测试的
命令、编译输出和验证结果保存在 `--work-dir` 中。验证器复用
`benchmark/official_suites/verification.py`。

本次本地证据位于 `tmp/commutation_optimization_20261102/`：

- `qllvm-compile-before`、`revision.txt`：修改前二进制及提交。
- `zz20-before.*`：修改前隔离 pass 时间及输出。
- `final-isolated.*`、`final-full.*`：最终编译命令、时间、原生 pass timing 及 QASM。
- `final-regression/results.json`：321 项验证结果。
- `zz20-validation.json`：大线路结构检查及三个输入态的数值检查。
- `final_benchmark.py`、`validate_zz20.py`：本次性能与大线路验证脚本。

本次只验证了上述线路和配置，不能据此声明所有输入语言、后端和动态控制流
均已完成回归。现有全局工作表尚未改为线程隔离，本改动不增加并发编译保证。
